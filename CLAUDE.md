# CLAUDE.md — Guitar Chords from Yandex Music

## 0. Что это за проект

Веб-приложение, которое:
1. Авторизуется в аккаунте Яндекс.Музыки (только владелец, токен в `.env`)
2. Показывает список плейлистов и треков из «Мне нравится»
3. По кнопке «Случайный трек» берёт случайную песню из выбранного плейлиста
4. Ищет гитарные аккорды на внешних сайтах (парсинг)
5. Показывает текст с аккордами, аппликатуры, табы перебора
6. Позволяет транспонировать тональность
7. Экспортирует результат в PDF (на клиенте)

**Статус:** MVP. Работает для одного пользователя (владельца токена).
Мультипользовательский OAuth — вне scope (юридические риски с неофициальным API Яндекса).

## 1. Стек

| Слой | Технология |
|---|---|
| Backend | Python 3.11+, FastAPI, Uvicorn |
| Яндекс API | библиотека `yandex-music` (неофициальная) |
| Парсинг аккордов | `httpx` + `selectolax` (быстрее BeautifulSoup) |
| Frontend | Jinja2-шаблоны + vanilla JS (без фреймворков на MVP) |
| Стили | минимальный CSS, тёмная тема по умолчанию |
| PDF | `jsPDF` + `html2canvas` на клиенте |
| Диаграммы аккордов | `svguitar` (клиент) |
| Табы перебора | генерация на клиенте (JS) по паттерну |
| Хостинг | Render.com (Web Service), автодеплой из GitHub |
| Секреты | `.env` + `python-dotenv`, файл в `.gitignore` |

**Правила:**

- Никаких тяжёлых фреймворков (React/Vue) на MVP — только серверный рендеринг + точечный JS.
- Все внешние запросы — с таймаутом 10 сек и retry 2 раза.
- Никаких ключей и токенов в коде. Только через `os.getenv`.

## 3. Переменные окружения (`.env`)

```text
YANDEX_MUSIC_TOKEN= # OAuth-токен, добывается вручную из DevTools
YANDEX_MUSIC_UID= # твой user id (число)
APP_HOST=0.0.0.0
APP_PORT=8000
LOG_LEVEL=INFO
```

**Как добыть токен (инструкция для пользователя):**
1. Открыть music.yandex.ru, залогиниться
2. DevTools → Network → фильтр `api`
3. Найти любой запрос к `api.music.yandex.net`, скопировать заголовок `Authorization: OAuth ...`
4. Вставить значение после `OAuth ` в `YANDEX_MUSIC_TOKEN`
5. UID виден в том же запросе в параметре `uid`

## 4. Функциональные требования

### 4.1 Яндекс.Музыка
- `GET /playlists` — список плейлистов пользователя (включая «Мне нравится»)
- `GET /playlist/{kind}` — треки плейлиста с обложками, исполнителем, названием
- `GET /random?kind={kind}` — редирект на `/track/{track_id}` со случайным треком
- Если токен протух → понятная страница «Токен истёк, обнови .env»

### 4.2 Парсинг аккордов
Приоритет источников (первый успешный — используется):

1. **AmDm.ru** — `https://amdm.ru/search/?q={artist}+{title}`
2. **MyChords.net** — `https://mychords.net/search?q={artist}+{title}`
3. **Ultimate-Guitar.com** — `https://www.ultimate-guitar.com/search.php?search_type=title&value={artist}+{title}`

**Правила парсинга:**
- Всегда ставить `User-Agent` реального браузера
- Если Cloudflare блокирует (UG) — молча переходить к следующему источнику
- Если ни один источник не дал результат → показать сообщение
  «Аккорды не найдены. Показать табы перебора?» с кнопкой на генерацию
- Никогда не кэшировать HTML источников на сервере (авторские права)

### 4.3 Отображение
- Текст песни с аккордами **над словами** (моноширинный шрифт, аккорды выделены цветом)
- Панель транспонирования: кнопки `-1`, `+1`, `Сброс`, выбор каподастра
- Блок «Аппликатуры»: SVG-диаграммы для всех уникальных аккордов в песне
- Блок «Перебор»: табы для 2-3 стандартных паттернов (4/4, 3/4, 6/8)
- Кнопка «Скачать PDF»

### 4.4 Обработка ошибок
| Ситуация | Поведение |
|---|---|
| Токен невалиден | Страница с инструкцией по обновлению |
| Трек — инструментал | Показать табы перебора + сообщение |
| Аккордов нет ни на одном сайте | Сообщение + кнопка «Показать табы» |
| Источник недоступен | Тихий фолбэк на следующий |
| Все источники упали | Сообщение с перечнем проверенных сайтов |
| Плейлист пуст | Заглушка «Добавь треки в избранное» |

## 5. Правила для Claude при написании кода

1. **Всегда** показывай полный файл, а не фрагмент — пользователь не программист.
2. **Никогда** не хардкодь токены, UID, URL-ы с ключами.
3. **Всегда** добавляй docstring к функциям на русском — пользователь будет читать.
4. **Всегда** оборачивай внешние HTTP-запросы в `try/except` с логированием.
5. **Никогда** не используй `print` — только `logging`.
6. **Перед** изменением структуры файлов — предупреди пользователя.
7. **После** каждого этапа — команда для локального теста
   (например: `uvicorn app.main:app --reload` и что открыть в браузере).
8. Если библиотека `yandex-music` сломалась — предложи 2-3 альтернативы,
   но не переписывай весь код без согласования.
9. Парсеры пиши **устойчиво к изменениям вёрстки**: искать по нескольким селекторам,
   логировать, что не нашлось.
10. Все тексты интерфейса — на русском.

## 6. Порядок разработки (этапы)

Claude ведёт пользователя по этапам. После каждого этапа — рабочая версия.

- **Этап 0.** Скелет проекта: FastAPI, пустая главная, `.env`, `requirements.txt`, README.
- **Этап 1.** Подключение к Яндекс.Музыке: список плейлистов на главной.
- **Этап 2.** Страница плейлиста со списком треков + кнопка «Случайный».
- **Этап 3.** Парсер AmDm (один источник) + страница трека с текстом аккордов.
- **Этап 4.** Транспонирование на клиенте (`transpose.js`).
- **Этап 5.** Аппликатуры через `svguitar`.
- **Этап 6.** Табы перебора (генерация по паттерну).
- **Этап 7.** PDF-экспорт (`jsPDF`).
- **Этап 8.** Добавление MyChords и Ultimate-Guitar как фолбэков.
- **Этап 9.** Деплой на Render.com через GitHub.
- **Этап 10.** Обработка всех ошибок из таблицы 4.4.

**Правило:** не начинать следующий этап, пока пользователь не подтвердил, что предыдущий работает.

## 7. Что вне scope (не делать на MVP)

- Мультипользовательская авторизация через Яндекс OAuth
- AI-транскрипция аккордов (Klangio и подобные)
- Мобильное приложение
- Сохранение истории / избранных аккордов в БД
- Собственная база аккордов

Если пользователь просит что-то из этого — напомнить, что это пост-MVP.
